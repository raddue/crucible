# Portable Quality-Gate Model Assurance Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use crucible:build to implement this plan task-by-task.

**Goal:** Preserve ordinary artifact PASS while reporting independently scoped `verified|configured|unknown` model assurance; block only callers that explicitly require verified QG evidence.

**Architecture:** A stdlib proof verifier reads a bounded, durable per-run inventory and optional protected host evidence; QG writes a final-integration marker only after full consumed-invocation reconciliation. Build and Warden persist and recheck the QG-leg proof tuple at every opted-in transition. No host adapter or consensus API expansion ships in this portable-core change; absent independent evidence cannot yield `verified`.

**Tech Stack:** Python stdlib, Markdown skill contracts, shell/Python selftests in `scripts/run_tests.sh`. Worktree `feat/746-gate-model-assurance`, not main checkout. Design: `docs/plans/2026-10-18-746-gate-model-assurance-design.md` (quality-gate PASS). The design is authoritative on precise canonical encoding, evidence trust, and roster semantics where this plan abbreviates them.

---

## Scope and release boundary

This is a **portable core**, not a high-assurance host deployment. Produce explicit unknown/configured states without Pi, 9router, or provider telemetry. Do not simulate a verified adapter, use dispatch `actual_model` as execution proof, certify an entire Warden run, modify the consensus server for first-adapter support, or add a global release block. With no protected journal and attested source records, even a syntactically complete inventory is never `verified`. The core verifier may support a future allowlisted adapter evidence interface, but its production default must fail closed on `verified`. `configured` requires exact approved local model/effort/route policy; absent approved mapping is `unknown`. Policy definitions and approval are separate from shipping this core; do not infer aliases or approve models while implementing.

Blast radius: QG round/chunk/siege/consensus orchestration, marker and optional ledger emit, Pi provenance checker, build gate ledger and recovery, Warden's single-marker and push path, tests/fixtures and behavioral evals. Existing PASS predicates remain intact; only explicit `qg-verified` policy adds a transition guard. Legacy runs with no opt-in stay portable.
